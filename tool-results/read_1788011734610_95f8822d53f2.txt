   448→- CALC-M-004-BUG-002 (random-number, Critical): The `randomIntInclusive(min, max)` function generated numbers OUTSIDE the requested range. For min=1, max=100, count=20, ALL 20 generated values were negative (in [-88, -8]) instead of in [1, 100]. Two compounding root causes:
   449→  (1) `x = secureRandomUint32() & 0xffffffff` — the `& 0xffffffff` bitwise operation in JS coerces both operands to 32-bit SIGNED integers and returns a signed result, so ~50% of generated `x` values were negative (specifically, when the high bit was set, the unsigned value in [2^31, 2^32-1] became a signed value in [-2^31, -1]).
   450→  (2) The rejection-sampling boundary was wrong: code used `span - (0x100000000 % span)` (= 4 for span=100), but the correct formula is `0x100000000 - (0x100000000 % span)` (= 4,294,967,200 for span=100).
